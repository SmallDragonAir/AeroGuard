# 路线图剩余项：在线生态功能设计备忘

README「后续计划」中仍未勾选的 5 项都依赖联网服务或外部数据源。
在引入任何在线依赖前，AeroGuard 需要先满足 README §安全原则中
对第三方诊断程序的要求（明确来源、程序白名单、完整性验证、
用户明确授权），因此以下各项**默认离线可运行、按需联网**。

## 1. 可选在线规则库（规则演进）

- 目标：让 `noise.py` / `classifier.py` 的启发式可从远端获取增量规则。
- 前置（本地先落地）：
  - 规则集版本化与签名（发布者私钥签名，公钥随 AeroGuard 分发）；
  - 规则快照缓存 + 哈希校验；离线时回退到内置规则；
  - 每条远端规则必须携带 `rule_id`、适用 `rule`/路径/扩展名单、
    理由模板与影响等级，JSON Schema 先行定稿。
- 不建议：把扫描结论本身放在远端判定——保持确定性本地计算。

## 2. 已知异常数据库（知识库）

- 目标：把"该插件+版本+异常的已知结论"沉淀为可查询记录。
- 前置：以现有 JSON 报告为输入做聚合与哈希（可先做**纯本地**版）：
  - 记录主键 = `content_hash(manifest) + 报告快照 evidence_digest`；
  - 本地库只存结论（"该差异已知为更新器导致，建议忽略"）与置信来源；
  - 报告链路里已经具备 `snapshot_id`/`evidence_digest`/`installed_version`
    等可链接字段（见 `history.py`），无需新数据模型即可起步。

## 3. 可信发布者体系（信任模型）

- 目标：标记可信来源的包，用于排序与风险解释。
- 前置（本地）：
  - 发布者身份 = 证书/公钥指纹，而不是包名（包名可仿冒）；
  - `manifest` 若带发布者字段，先以**本机信任清单**匹配，不做远程权威；
  - 报告中仅显示"未在本机信任清单中"，不输出贬损性结论。

## 4. 插件仓库 / Hub（分发协议）

- 目标：搜索与拉取插件。
- 前置：
  - 目录条目元数据与 AeroGuard 的安装前检查（`management._safe_extract_zip`
    等安全逻辑）复用同一套校验，Hub 来源不豁免安全检查；
  - 下载校验：大小 + SHA-256 + 发布者签名三重验证后再进暂存区；
  - 服务端可先由一个静态 manifest 列表模拟，协议与实现解耦。

## 5. 安装与更新管理（更新器）

- 目标：检测并应用插件更新。
- 前置：
  - 更新包走与「安装」完全相同的 `PreinstallInspection` + 事务回滚路径
    （现有 `install`/`rollback_install` 已支持"替换保留旧版"，可直接复用）；
  - 仅当版本源提供签名与哈希时才自动应用，否则只提示"存在更新"；
  - 版本先后**不靠版本号字符串推断**（README 已声明），更新依据
    以来源元数据或校验和变化为准。

## 共同原则

- 每项都先有**本地可用**的子集与确定性测试，再谈联网；
- 网络层建议以"可选插件/可选开关"形态提供，核心不依赖网络；
- 与第三方服务通信前需向用户明示数据去向与用途。
